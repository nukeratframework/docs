Вызов события в NukeScript обязателен — без него скрипт не запустится. Поэтому в каждом скрипте должен быть хотя бы один такой вызов.

Формат вызова: `event.<name>:my_function()`

- `event`: зарезервированное слово, начало вызова события
- `<name>`: имя события
- `my_function()`: функция, которая выполнится при срабатывании события

Пример:

```python
def on_new_host(row):
    cmd(row["tag"], "whoami")

event.new_host:on_new_host()
```

Первая функция, которую вызывает событие, называется функцией точки входа события; для неё действуют особые правила синтаксиса:

1. Вызов точки входа не должен принимать аргументов
2. У функции точки входа по умолчанию должен быть ровно один параметр (имя любое; ниже используем `row`)
3. Каждая строка `event.<name>:handler()` должна быть в конце скрипта, после всего остального кода

Ниже — пример с неверным синтаксисом:

```python
def on_new_host(row, some_parameter):
    cmd(row["tag"], "whoami")

event.new_host:on_new_host("example")
```

Главный параметр функции точки входа всегда получает словарь с содержимым события — это строка таблицы БД, которая вызвала событие.

Чтобы понять, что в словаре, полезно знать схему столбцов таблиц. Подробнее — в разделе [Столбцы базы данных](#столбцы-базы-данных).

## Каталог событий

Список доступных событий:

| Событие | Описание | Ключи |
| --- | --- | --- |
| `new_host` | Первый check-in | `tag`, `ip`, `external_ip`, `listener`, `arch`, `os`, `user`, `hostname`, `status`, `delay`, `first_seen`, `last_seen`, `next_checkin`, … |
| `removed_host` | Хост удалён с сервера команды | Те же ключи, что у `new_host` |
| `expired_host` | Хост пропустил окно check-in | Те же ключи, что у `new_host` |
| `new_queue_line` | Задача поставлена в очередь до выполнения имплантом | `tag`, `host`, `type`, `command`, `input`, `parameters`, `is_completed`, `is_ready`, … |
| `implant_error` | Задача очереди завершилась с ошибкой | Содержит непустое поле `error` |
| `task_completed` | Задача очереди выполнена без ошибки | `is_completed`, `custom_response` при завершении с пользовательским сообщением |
| `new_checkin` | Новый check-in | `tag`, `host`, `type` |
| `keylogger_update` | Обновление кейлоггера | `tag`, `content`, `host_tag` |
| `folders_update` | Вставка или обновление в обозревателе файлов | `host`, `path`, `type`, `modified`, `size` |
| `process_update` | Вставка или обновление дерева процессов | `tag`, `host`, `tree` |
| `output_received` | Новый вывод терминала | `terminal_id`, `host`, `input`, `output` |
| `credentials_update` | Новая сохранённая учётная запись | `tag`, `name`, `host`, `content` |
| `listeners_update` | Добавлен новый listener | `tag`, `type`, `protocol`, `config` |
| `heartbeat_1s` | Срабатывает каждую секунду | |
| `heartbeat_5s` | Срабатывает каждые 5 секунд | |
| `heartbeat_10s` | Срабатывает каждые 10 секунд | |
| `heartbeat_15s` | Срабатывает каждые 15 секунд | |
| `heartbeat_30s` | Срабатывает каждые 30 секунд | |
| `heartbeat_1m` | Срабатывает каждую минуту | |
| `heartbeat_5m` | Срабатывает каждые 5 минут | |
| `heartbeat_10m` | Срабатывает каждые 10 минут | |
| `heartbeat_15m` | Срабатывает каждые 15 минут | |
| `heartbeat_20m` | Срабатывает каждые 20 минут | |
| `heartbeat_30m` | Срабатывает каждые 30 минут | |
| `heartbeat_60m` | Срабатывает каждые 60 минут | |
| `heartbeat_2h` | Срабатывает каждые 2 часа | |
| `heartbeat_12h` | Срабатывает каждые 12 часов | |
| `heartbeat_1d` | Срабатывает каждый день | |
| `heartbeat_3d` | Срабатывает каждые 3 дня | |
| `heartbeat_7d` | Срабатывает каждые 7 дней | |
| `heartbeat_15d` | Срабатывает каждые 15 дней | |
| `heartbeat_30d` | Срабатывает каждые 30 дней | |
