---
title: AES sync
---

У каждого listener есть интерфейс связи, чтобы принимать AES-ключи связи, которыми импланты шифруют сообщение. Это нужно для того, чтобы, если имплант собран на конкретном сервере команды, остальные серверы команды тоже получили этот AES-ключ и могли расшифровать сообщения импланта.

## Как это работает

Пока имплант компилируется, сервер команды берёт список настроенных серверов и отправляет запрос каждому настроенному listener с AES-ключом связи этого импланта.

Но у всех серверов команды должен быть один и тот же secret key AES sync, чтобы принять и сохранить этот AES-ключ. Если он другой, имплант будет общаться только с тем сервером команды, на котором его собрали: только он сможет расшифровать сообщения.

## Как настроить

1. На сервере команды выполни такую команду:

```bash
./nukerat.py server config set server.aes_sync.secret_key 1234567
```

Эту же команду нужно выполнить на всех серверах команды.

2. Проверь конфигурацию в файле конфигурации сервера команды:

```bash
./nukerat.py server config list
```

Должно вернуться что-то вроде:

```toml
[server.aes_sync]
secret_key = 1234567
sync_path = "/sync"
```

3. Перезапусти серверы команды и продолжай компиляцию импланта как обычно.

## Sync path

Можно также поменять путь синхронизации AES-ключей. Для этого используй такую команду:

```bash
./nukerat.py server config set server.aes_sync.sync_path /example
```

Это полезно в первую очередь, чтобы уйти от сигнатур вокруг URL listener, если ты используешь стандартный HTTP-канал.
