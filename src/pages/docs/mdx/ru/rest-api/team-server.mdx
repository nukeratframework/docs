Эндпоинты REST API сервера команды.

Все эндпоинты, кроме `/auth/login`, требуют заголовок `Authorization: Bearer <token>`. Токен получают через `/auth/login`.

### Аутентификация

Создание и проверка сессий аутентификации операторов.

<Collapsible className="mb-4">
  <CollapsibleTrigger className="flex w-full items-center gap-3 rounded-[11px] border border-fd-border bg-fd-card px-[15px] py-[10px] text-left text-sm font-medium">
    <span className="rounded-[6px] bg-emerald-500/15 px-2 py-1 font-semibold text-emerald-400">POST</span>
    <span className="font-[400] text-[16px]">/auth/login</span>
  </CollapsibleTrigger>
  <CollapsibleContent className="mt-3 rounded-lg border border-fd-border bg-fd-card p-4 text-sm text-fd-muted-foreground">
    <h2 className="api-section-title api-section-title--explanation">Пояснение</h2>
    Аутентификация оператора по имени пользователя, паролю и secret. Возвращает JWT. Если любое из полей `user`, `pass` или `secret` отсутствует или пустое, ответ: `{"status": "failure", "message": "user, pass and secret are required"}`.

    **Важно:** значения `user`, `pass` и `secret` нужно взять из ключа оператора, сгенерированного на team server. Пример:

    ```
    admin:F9VhtamxN:yKu31sGWKXYPbnRq52cg
    ```

    В примере выше:

    
    **user** = `admin`<br/>
    **pass** = `F9VhtamxN`<br/>
    **secret** = `yKu31sGWKXYPbnRq52cg`<br/>

    <h2 className="api-section-title api-section-title--primary">Запрос</h2>

    ```json
    {
      "user": "admin",
      "pass": "password",
      "secret": "secret"
    }
    ```


    <h2 className="api-section-title api-section-title--compact">Ответ</h2>

    <Tabs className="api-tabs" items={['Success', 'Failure']}>
      <Tab value="Success">
        ```json
        {
          "status": "success",
          "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
        }
        ```
      </Tab>
      <Tab value="Failure">
        <Tabs className="api-tabs" items={['Credentials', 'Validation']}>
          <Tab value="Credentials">
            ```json
            {
              "status": "failure",
              "message": "Invalid credentials"
            }
            ```
          </Tab>
          <Tab value="Validation">
            ```json
            {
              "status": "failure",
              "message": "Invalid request",
              "errors": [
                { "field": "<field>", "message": "<detail>" }
              ]
            }
            ```
          </Tab>
        </Tabs>
      </Tab>
    </Tabs>

    <h2 className="api-section-title api-section-title--primary">Особый случай: `-f` / `--file`</h2>

    Прикрепить байты файла можно одним из трёх способов:

    1. Добавьте к строке `command` флаг `--__tmp_file_bytes__` и payload в base64 (как в клиенте NukeRat).
    2. Передайте отдельное JSON-поле `__tmp_file_bytes__` с payload в base64 (строка `command` остаётся без вложения).
    3. Отправьте тело запроса как сырые байты файла и поместите URL-encoded JSON с метаданными в заголовок `x-terminal-meta` (те же поля, что в JSON-теле). Сервер сохраняет сырое тело как payload загрузки.

    **Пример (inline-флаг):**

    ```
    upload -f payload.exe -o C:/Temp/payload.exe --__tmp_file_bytes__ SGVsbG8=
    ```

    <h2 className="api-section-title api-section-title--primary">Особый случай: `download`</h2>

    Команда `download` не возвращает один JSON с base64 в `message`. Ответ имеет `Content-Type: application/x-ndjson`: JSON-события построчно (`progress`, затем метаданные `chunk` и сырые байты, затем `success` или `failure`). Необязательные поля `download_id` и `download_file` отслеживают прогресс в очереди загрузок на сервере.

    <h2 className="api-section-title api-section-title--primary">Запрос</h2>

    ```json
    {
      "command": "whoami",
      "host_tag": "600d4",
      "source_terminal": "terminal_123"
    }
    ```

    <Callout type="info">
      Имейте в виду: `source_terminal` обязателен, но только идентифицирует терминал клиента, отправивший запрос. На выполнение команды не влияет.
