Setting an event call in NukeScript is required for the script to run. Because of that, every script is expected to include at least one event call.

The event call follows this format: `event.<name>:my_function()`

- `event`: reserved keyword that marks the start of the event call
- `<name>`: event name
- `my_function()`: function that runs when the event fires

Here is an example:

```python
def on_new_host(row):
    cmd(row["tag"], "whoami")

event.new_host:on_new_host()
```

The first function called by the event is called the event entrypoint function, and it has specific syntax rules:

1. The entrypoint call must never receive any parameters
2. The entrypoint function should contain only one parameter by default (you can use any name, but we will use `row` by default)
3. Every `event.<name>:handler()` line must appear at the end of the script, after all other code

Below is an example with incorrect syntax:

```python
def on_new_host(row, some_parameter):
    cmd(row["tag"], "whoami")

event.new_host:on_new_host("example")
```

The main parameter of the entrypoint function always receives a dictionary with the event content, which is simply the database row that triggered the event.

It helps to know the database column layout to understand what is inside that dictionary. For more on that, see [Database columns](#database-columns).

## Events catalog

Below is the list of available events:

| Event | Description | Keys |
| --- | --- | --- |
| `new_host` | First check in | `tag`, `ip`, `external_ip`, `listener`, `arch`, `os`, `user`, `hostname`, `status`, `delay`, `first_seen`, `last_seen`, `next_checkin`, … |
| `removed_host` | Host removed from the team server | Same keys as `new_host` |
| `expired_host` | Host missed the check in window | Same keys as `new_host` |
| `new_queue_line` | Task queued before the implant runs | `tag`, `host`, `type`, `command`, `input`, `parameters`, `is_completed`, `is_ready`, … |
| `implant_error` | Queue task failed | Includes a non empty `error` |
| `task_completed` | Queue task finished without error | `is_completed`, `custom_response` when completed with a custom message |
| `new_checkin` | New check in | `tag`, `host`, `type` |
| `keylogger_update` | Keylogger update | `tag`, `content`, `host_tag` |
| `folders_update` | Folder explorer insert or update | `host`, `path`, `type`, `modified`, `size` |
| `process_update` | Process tree insert or update | `tag`, `host`, `tree` |
| `output_received` | New terminal output | `terminal_id`, `host`, `input`, `output` |
| `credentials_update` | New stored credential | `tag`, `name`, `host`, `content` |
| `listeners_update` | New listener inserted | `tag`, `type`, `protocol`, `config` |
| `heartbeat_1s` | Runs every 1 second | |
| `heartbeat_5s` | Runs every 5 seconds | |
| `heartbeat_10s` | Runs every 10 seconds | |
| `heartbeat_15s` | Runs every 15 seconds | |
| `heartbeat_30s` | Runs every 30 seconds | |
| `heartbeat_1m` | Runs every 1 minute | |
| `heartbeat_5m` | Runs every 5 minutes | |
| `heartbeat_10m` | Runs every 10 minutes | |
| `heartbeat_15m` | Runs every 15 minutes | |
| `heartbeat_20m` | Runs every 20 minutes | |
| `heartbeat_30m` | Runs every 30 minutes | |
| `heartbeat_60m` | Runs every 60 minutes | |
| `heartbeat_2h` | Runs every 2 hours | |
| `heartbeat_12h` | Runs every 12 hours | |
| `heartbeat_1d` | Runs every 1 day | |
| `heartbeat_3d` | Runs every 3 days | |
| `heartbeat_7d` | Runs every 7 days | |
| `heartbeat_15d` | Runs every 15 days | |
| `heartbeat_30d` | Runs every 30 days | |
