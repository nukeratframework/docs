Relay는 임플란트 기능으로, 네트워크 내부에서 임플란트끼리 통신할 수 있게 합니다. 호스트에 인터넷 접근이 없거나 네트워크가 잠겨 있을 때 피벗에 유용합니다.

Relay는 **SMB**와 **TCP**를 지원합니다. SMB는 Windows 전용입니다.

## 사용 방법

이해를 돕기 위해 예시 시나리오를 들겠습니다.

호스트 A가 있고, 같은 네트워크에 외부로 나갈 경로가 없어 팀 서버에 직접 도달할 수 없는 호스트 B가 있습니다.

이 경우 다음 단계를 따릅니다.

  <Steps>
    <Step>
      ### 사전 구성된 임플란트
      먼저 호스트 B에서 relay 통신용으로 미리 구성된 임플란트가 이미 실행 중인지 확인합니다.

      relay 임플란트 빌드 방법은 [Relay stageless 임플란트](/docs/client/implants/creation#relay-stageless-임플란트)를 참고하세요.
    </Step>
    <Step>
      ### 호스트 A에서 relay 설정

      TCP relay:
        ```
        relay create --listen 8888 --target implant://192.168.15.10:9090 --channel tcp
        ```
      SMB relay(Windows 전용):
        ```
        relay create -l 445 --target server://192.168.15.10:9090 -c smb --pipe test --tls
        ```
    매개변수:
        - `--listen` / `-l`: 임플란트가 열고 수신 대기(listen)하는 포트(기본 relay id로도 사용)
        - `--target` / `-t`: `implant://host:port` 또는 `server://host:port` 형식의 다운스트림 엔드포인트
        - `--channel` / `-c`: `tcp` 또는 `smb`
        - `--pipe`: SMB named pipe. `test` 같은 짧은 이름 또는 Windows에서 전체 `\\pipe\\name` 경로
        - `--tls`: 대상이 `server://`일 때 HTTP 대신 HTTPS로 팀 서버에 POST
        - `--id`: `relay delete`용 relay id 또는 기본 listen 포트 id 재정의
    </Step>
    <Step>
      ### relay 관리
      인수 없이 `relay`를 실행하면 활성 relay(listen 포트, target, mode, status) 목록이 표시됩니다.

      relay를 중지하려면:
        ```
        relay delete --id 8888
        ```
    </Step>
    <Step>
      ### relay 테스트
      그 후 임플란트 B가 완전히 동작해야 합니다.
    </Step>
  </Steps>


### Target prefix

`target` 매개변수는 항상 `implant://` 또는 `server://` prefix를 받습니다. 팀 서버에 도달하기 위해 트래픽을 HTTP로 변환할 시점을 임플란트에 알립니다.

어느 쪽을 쓸지는 간단합니다. 다음 홉이 팀 서버면 `server://`(종료 지점)를 사용합니다. 다른 임플란트로 트래픽을 넘기면 `implant://`를 사용합니다.

### 누적 지연

Relay는 각 임플란트에 구성된 delay를 존중하며 트래픽을 전달합니다. 여러 호스트를 거치면 delay가 쌓여 응답 시간이 눈에 띄게 느려질 수 있습니다.

## 동작 방식

relay가 생성되면 구성된 포트에서 listen을 시작합니다.

트래픽이 들어오면 임플란트는 페이로드를 복호화하고 `chain`에 자신의 host tag를 추가한 뒤 다시 암호화하여 target으로 전달합니다.

전달되는 JSON은 다음 구조를 따릅니다.

```json
{
  "source": "hostB",
  "content": [
    {
      "option": "output",
      "type": "terminal",
      "task_tag": "k7F2a9",
      "output": "desktop\\user\r\n"
    }
  ],
  "chain": ["hostB", "hostA"]
}
```

target이 다른 임플란트면 페이로드는 그대로 전달됩니다. target이 팀 서버면 임플란트는 트래픽을 HTTP로 변환해 upstream으로 보냅니다.

### 통신 암호화

모든 relay 트래픽은 컴파일 시 각 임플란트에 내장된 master AES 키로 암호화됩니다. 같은 팀 서버용으로 빌드된 모든 임플란트는 동일한 키를 공유합니다.

이렇게 하면 키 교환을 위해 사전 handshake가 필요 없어 해당 종류의 트래픽 시그니처도 줄어듭니다.

master AES 키를 변경하려면 `server.conf`의 `[implants]` 섹션에서 `relay_aes_key`를 설정합니다. 값은 최소 32바이트로 디코딩되어야 합니다(base64 또는 hexadecimal). 변경 후 임플란트를 다시 빌드하세요.

**참고:** master AES 키를 변경하면 이전 키를 쓰는 임플란트와의 통신이 끊깁니다.

### Windows

- **TCP**는 `ws2_32.dll`의 `WSAStartup`, `socket`, `bind`, `listen`, `accept`, `connect`, `send`, `recv`, `closesocket`, `getaddrinfo`, `freeaddrinfo`를 사용합니다.

- **SMB**는 `kernel32.dll`의 `CreateNamedPipeA`, `ConnectNamedPipe`, `CreateFileA`, `WaitNamedPipeA`, `PeekNamedPipe`, `ReadFile`, `WriteFile`, `DisconnectNamedPipe`, `CloseHandle`을 사용합니다.

### Linux

POSIX 소켓(`sys/socket.h`)과 `socket`, `bind`, `listen`, `accept`, `connect`, `send`, `recv`, `setsockopt`, `getaddrinfo` / `freeaddrinfo`를 사용합니다. SMB는 지원하지 않습니다.

### macOS

Go stdlib의 `net.Listen`, `net.Accept`, `net.Dial`, `io.Copy`를 사용합니다. SMB는 지원하지 않습니다.
