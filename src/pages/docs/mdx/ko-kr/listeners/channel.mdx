임플란트가 팀 서버와 통신하려면, 해당 임플란트용으로 이미 구성된 채널이 필요합니다.

현재 채널 카테고리는 두 가지입니다.

- HTTP/HTTPS
- Custom

## HTTP/HTTPS 채널

설정하기 가장 간단하고 일반적인 채널입니다. 임플란트가 접속할 URL 외에 추가 구성은 필요하지 않습니다.

이 채널을 만들 때 다음과 같은 고급 설정도 조정할 수 있습니다.

- URL 경로 변경(예: `https://example.com/path` → `https://example.com/path/custom`)
- 응답 헤더
- 임플란트 요청 및 리스너 응답용 사용자 지정 body 템플릿

## 커스텀 채널

가장 복잡하지만 유연성도 가장 큰 채널 유형입니다. 다음처럼 매우 특수한 통신이 필요할 때 커스텀 채널이 필수입니다.

- Telegram
- Discord
- Dropbox

프리셋이 없으므로 모든 항목을 수동으로 구성해야 합니다. 임플란트 생성 단계에서 채널과 통신하기 위한 사용자 지정 코드 스니펫을 작성해야 하는 부분도 포함됩니다.

생성 UI에는 "custom channel" 옵션이 없습니다. 수동으로 설정해야 하기 때문입니다. 자세한 내용은 [커스텀 채널](/docs/custom-channels)을 참고하세요.

## 다른 채널 유형은?

일부 프레임워크는 DNS, DoH, mTLS 등 대안 채널을 여전히 지원합니다. NukeRat는 Telegram, Google Drive 등 외부 통신 서비스와의 통합 수요 등 최근 트렌드에 맞추기 위해 위 두 가지 채널 유형을 선택했습니다.

앞으로 공식적으로 더 많은 채널 유형을 추가할 계획은 없습니다.

DNS처럼 특정 채널 유형이 여전히 필요하다면 **커스텀 채널**로 해당 통신을 직접 구현해야 합니다.

## HTTP 채널 생성

HTTP 채널(SSL 없음)은 만들기 가장 쉬운 유형입니다. 아래 단계를 따르세요.

  <Steps>
    <Step>
      ### 리스너 탭 열기
      **NukeRat** > **Listeners** > **Add**를 엽니다.
    </Step>
    <Step>
      ### 필드 입력
      <ImageZoom src={listenerForm} alt="Listener Form" className="h-[30rem] tutorial_img" style={{ marginLeft: 0, marginRight: 0, display: 'block' }} />
      - **Name**: 리스너를 쉽게 구분할 수 있는 이름을 지정합니다.
      - **Type**: `Channel` 선택
      - **Channel**: `http` 또는 `https` 선택
      - **Server**: 리스너를 생성할 팀 서버 선택(사전에 구성되어 있어야 함)
      - **Port to open**: 사용할 포트
    </Step>
    <Step>
      ### **Create** 클릭
      모든 항목이 올바르면 리스너가 생성되어 리스너 탭 목록에 표시됩니다.
      <ImageZoom src={listenerOk} alt="Listener Ok" className="h-[6.5rem] tutorial_img" style={{ marginLeft: 0, marginRight: 0, display: 'block' }} />
    </Step>
  </Steps>

생성을 마치면 임플란트로 방금 설정한 채널과 통신할 수 있습니다.

HTTP 채널(SSL 없음)은 임플란트 빌드 시 공유 AES 256 키로 임플란트 요청과 리스너 응답을 암호화합니다. HTTP 세션이 캡처되더라도 해당 키 없이는 body를 읽을 수 없습니다. 와이어상 페이로드 형태는 [통신 암호화](/docs/rest-api/implants#통신-암호화)를 참고하세요.

## HTTPS 및 인증서

SSL을 사용하려면 리스너 생성 시 **Channel** 필드에서 `https`를 선택합니다. 포트 필드 아래에 **Certificate** 섹션이 나타납니다. **Source**에서 self signed 또는 manual을 선택합니다.

자체 서명(self signed) 인증서는 NukeRat가 `openssl`로 자동 생성하며, 유효 기간, CN, SAN, 키 유형 등 생성 설정을 사용자 지정할 수 있습니다.

일부 필드는 placeholder에 예시 값이 표시됩니다. 당연히 그 값을 그대로 사용하면 안 됩니다. 인증서 서명 매칭을 통한 탐지로 이어질 수 있습니다.

manual 인증서의 경우 인증서와 개인 키 PEM을 붙여 넣거나 업로드합니다(예: Namecheap 같은 제공업체에서 발급).

SSL 없는 HTTP 채널과 마찬가지로 HTTPS 채널도 임플란트 body에 동일한 AES 256 암호화를 사용합니다. TLS는 전송 계층을 보호하며, SSL/TLS 검사 환경에서도 body는 암호화된 상태로 유지됩니다.

## 고급 사용자 지정

HTTP/HTTPS 채널에는 **Advanced** 아래 필드가 있습니다.

- **Endpoint path**: 임플란트가 통신에 사용할 URL 경로
- **Response headers**: 채널의 응답 헤더
- **Custom body**: 프리셋(`off`, `custom`, 또는 내장 `json`/`xml` 예시) 및 custom body가 `off`가 아닐 때 선택적인 **Listener response** 및 **Implant request** 템플릿

## Custom body

기본적으로 임플란트와 서버 간 통신은 단순합니다. 문자열을 암호화해 body에 붙입니다. 예:

```http
POST /api HTTP/1.1
Host: example.com

U2FsdGVkX1/Z8mN3kL9qP2vX7dQ4jK1mR5sT8uW2xY3aB6cD9e...
```

body는 특정 구조 없이 암호화된 데이터 덩어리일 뿐입니다. custom body를 사용하면 임플란트와 서버 간 공유 구조를 정의할 수 있습니다. 예:

**서버 응답:**
```http
{
  "status": "ok",
  "data": "§content§"
}
```

**임플란트 요청:**
```http
{
  "type": "telemetry",
  "event": "sync",
  "payload": "§content§",
}
```

위 예시처럼 구성하면 채널은 정의된 형식으로 응답을 보내고 임플란트 요청도 같은 형식을 기대합니다.

채널 생성 UI에 custom body 예시를 일부 추가했지만, 그대로 사용하는 것은 권장하지 않습니다. body 서명 매칭을 통한 탐지가 발생할 수 있습니다.

### 참고

1. 임플란트가 올바르게 통신하려면 임플란트 생성 시 동일한 **Listener response** 및 **Implant request** 템플릿을 재현하세요. 리스너는 런타임에 `implantBody`를 읽고 `listenerResponse`로 답장을 감쌉니다([임플란트 리스너 API](/docs/rest-api/implants#요청-본문-템플릿-implantbody) 참고).
2. HTTP/HTTPS 채널에서 `implantBody`가 비어 있거나 정확히 `§content§`이면 전체 raw 요청 body가 암호화됩니다. 사용자 지정 구조를 쓰면 `§content§` 슬라이스만 암호화됩니다. 리스너는 복호화 전에 해당 슬라이스를 추출합니다.
