endpointهای API برای سرور تیم.

به‌جز `/auth/login`، همهٔ endpointها به هدر `Authorization: Bearer <token>` نیاز دارند. توکن را از `/auth/login` بگیرید.

### احراز هویت

ایجاد و اعتبارسنجی sessionهای احراز هویت برای اپراتورها.

<Collapsible className="mb-4">
  <CollapsibleTrigger className="flex w-full items-center gap-3 rounded-[11px] border border-fd-border bg-fd-card px-[15px] py-[10px] text-left text-sm font-medium">
    <span className="rounded-[6px] bg-emerald-500/15 px-2 py-1 font-semibold text-emerald-400">POST</span>
    <span className="font-[400] text-[16px]">/auth/login</span>
  </CollapsibleTrigger>
  <CollapsibleContent className="mt-3 rounded-lg border border-fd-border bg-fd-card p-4 text-sm text-fd-muted-foreground">
    <h2 className="api-section-title api-section-title--explanation">توضیح</h2>
    Authenticates an operator using username, password, and secret. Returns the authentication JWT. When any of `user`, `pass`, or `secret` is missing or empty, the response is `{"status": "failure", "message": "user, pass and secret are required"}`.

    **Important:** You must extract `user`, `pass`, and `secret` from the operator key generated on the team server. For example:

    ```
    admin:F9VhtamxN:yKu31sGWKXYPbnRq52cg
    ```

    In the example above:

    
    **user** = `admin`<br/>
    **pass** = `F9VhtamxN`<br/>
    **secret** = `yKu31sGWKXYPbnRq52cg`<br/>

    <h2 className="api-section-title api-section-title--primary">درخواست</h2>

    ```json
    {
      "user": "admin",
      "pass": "password",
      "secret": "secret"
    }
    ```

### Implant interaction

<Collapsible className="mb-4">

  <CollapsibleContent className="mt-3 rounded-lg border border-fd-border bg-fd-card p-4 text-sm text-fd-muted-foreground">
    <h2 className="api-section-title api-section-title--explanation">توضیح</h2>
    Sends a terminal command to an implant.

    <h2 className="api-section-title api-section-title--primary">Special case: `-f` / `--file`</h2>

    Attach file bytes in one of three ways:

    1. Append `--__tmp_file_bytes__` followed by a base64 payload to the `command` string (same as the NukeRat client).
    2. Send a separate JSON field `__tmp_file_bytes__` with base64 payload (the command string stays clean).
    3. Send the request body as raw file bytes and put a URL-encoded JSON metadata object in the `x-terminal-meta` header (same fields as the JSON body). The server stores the raw body as the upload payload.

    **Example (inline flag):**

    ```
    upload -f payload.exe -o C:/Temp/payload.exe --__tmp_file_bytes__ SGVsbG8=
    ```

    <h2 className="api-section-title api-section-title--primary">Special case: `download`</h2>

    The `download` command does not return a single JSON body with base64 in `message`. It responds with `Content-Type: application/x-ndjson`: newline-delimited JSON events (`progress`, then `chunk` metadata followed by raw bytes, then `success` or `failure`). Optional fields `download_id` and `download_file` track progress in the server download queue.

    <h2 className="api-section-title api-section-title--primary">درخواست</h2>

    ```json
    {
      "command": "whoami",
      "host_tag": "600d4",
      "source_terminal": "terminal_123"
    }
    ```

    <Callout type="info">
      Note that `source_terminal` is required, but it only identifies which client terminal sent the request. It does not affect command execution.
    </Callout>
