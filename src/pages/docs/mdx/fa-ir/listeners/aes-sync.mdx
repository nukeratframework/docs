---
title: AES sync
---

هر listener یک رابط ارتباطی دارد تا کلیدهای AES ارتباطی را بگیرد؛ همان کلیدهایی که ایمپلنت‌ها برای رمز کردن پیام استفاده می‌کنند. این برای آن است که اگر یک ایمپلنت روی یک team server مشخص کامپایل شود، team serverهای دیگر هم آن کلید AES را بگیرند و بتوانند پیام‌های ارتباطی ایمپلنت را رمزگشایی کنند.

## چطور کار می‌کند

موقع کامپایل ایمپلنت، team server فهرست سرورهای پیکربندی‌شده را برمی‌دارد و به هر listener پیکربندی‌شده یک درخواست می‌فرستد، همراه با کلید AES ارتباطی آن ایمپلنت.

ولی همهٔ team serverها باید همان secret key مربوط به AES sync را داشته باشند تا این کلید AES را بپذیرند و ذخیره کنند. اگر فرق داشته باشد، ایمپلنت فقط با همان team serverی که روی آن کامپایل شده حرف می‌زند، چون فقط همان‌جا می‌تواند پیام‌ها را رمزگشایی کند.

## چطور پیکربندی کنیم

1. روی team server این دستور را بزن:

```bash
./nukerat.py server config set server.aes_sync.secret_key 1234567
```

همین دستور را باید روی همهٔ team serverها اجرا کنی.

2. پیکربندی را در فایل پیکربندی team server تأیید کن:

```bash
./nukerat.py server config list
```

باید چیزی شبیه این برگرداند:

```toml
[server.aes_sync]
secret_key = 1234567
sync_path = "/sync"
```

3. team serverها را ری‌استارت کن و مثل همیشه برو سراغ کامپایل ایمپلنت.

## Sync path

می‌توانی مسیر همگام‌سازی کلیدهای AES را هم عوض کنی. برای این کار از این دستور استفاده کن:

```bash
./nukerat.py server config set server.aes_sync.sync_path /example
```

این بیشتر به درد می‌خورد تا از امضاهای دور URLِ listener دور بمانی، اگر از کانال HTTP پیش‌فرض استفاده می‌کنی.
