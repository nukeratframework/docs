فراخوانی رویداد در NukeScript برای اجرای اسکریپت لازم است؛ بنابراین انتظار می‌رود هر اسکریپت حداقل یک فراخوانی رویداد داشته باشد.

فرمت فراخوانی: `event.<name>:my_function()`

- `event`: کلمهٔ رزروشده که شروع فراخوانی رویداد را مشخص می‌کند
- `<name>`: نام رویداد
- `my_function()`: تابعی که با رخ دادن رویداد اجرا می‌شود

مثال:

```python
def on_new_host(row):
    cmd(row["tag"], "whoami")

event.new_host:on_new_host()
```

اولین تابعی که رویداد فراخوانی می‌کند، تابع نقطهٔ ورود (entrypoint) رویداد نام دارد و قواعد نحوی خاص خود را دارد:

1. فراخوانی entrypoint نباید هیچ پارامتری بگیرد
2. تابع entrypoint به‌طور پیش‌فرض فقط یک پارامتر دارد (نام دلخواه؛ در اینجا از `row` استفاده می‌کنیم)
3. هر خط `event.<name>:handler()` باید در انتهای اسکریپت، بعد از بقیهٔ کد باشد

در زیر مثالی با نحو نادرست:

```python
def on_new_host(row, some_parameter):
    cmd(row["tag"], "whoami")

event.new_host:on_new_host("example")
```

پارامتر اصلی تابع entrypoint همیشه dictionaryای با محتوای رویداد می‌گیرد — همان سطر پایگاه داده‌ای که رویداد را راه‌انداخته است.

برای فهم محتوای dictionary مفید است چیدمان ستون‌های پایگاه داده را بدانید. بیشتر در [ستون‌های پایگاه داده](#ستون‌های-پایگاه-داده).

## فهرست رویدادها

در زیر فهرست رویدادهای موجود است:

| رویداد | توضیح | کلیدها |
| --- | --- | --- |
| `new_host` | اولین check-in | `tag`, `ip`, `external_ip`, `listener`, `arch`, `os`, `user`, `hostname`, `status`, `delay`, `first_seen`, `last_seen`, `next_checkin`, … |
| `removed_host` | میزبان از team server حذف شد | همان کلیدهای `new_host` |
| `expired_host` | میزبان پنجرهٔ check-in را از دست داد | همان کلیدهای `new_host` |
| `new_queue_line` | task قبل از اجرای implant در صف قرار گرفت | `tag`, `host`, `type`, `command`, `input`, `parameters`, `is_completed`, `is_ready`, … |
| `implant_error` | task صف با خطا مواجه شد | شامل `error` غیرخالی |
| `task_completed` | task صف بدون خطا تمام شد | `is_completed`, `custom_response` وقتی با پیام سفارشی تمام شده |
| `new_checkin` | check-in جدید | `tag`, `host`, `type` |
| `keylogger_update` | به‌روزرسانی keylogger | `tag`, `content`, `host_tag` |
| `folders_update` | درج یا به‌روزرسانی مرورگر فایل | `host`, `path`, `type`, `modified`, `size` |
| `process_update` | درج یا به‌روزرسانی درخت فرایند | `tag`, `host`, `tree` |
| `output_received` | خروجی ترمینال جدید | `terminal_id`, `host`, `input`, `output` |
| `credentials_update` | credential ذخیره‌شدهٔ جدید | `tag`, `name`, `host`, `content` |
| `listeners_update` | listener جدید درج شد | `tag`, `type`, `protocol`, `config` |
| `heartbeat_1s` | هر ۱ ثانیه | |
| `heartbeat_5s` | هر ۵ ثانیه | |
| `heartbeat_10s` | هر ۱۰ ثانیه | |
| `heartbeat_15s` | هر ۱۵ ثانیه | |
| `heartbeat_30s` | هر ۳۰ ثانیه | |
| `heartbeat_1m` | هر ۱ دقیقه | |
| `heartbeat_5m` | هر ۵ دقیقه | |
| `heartbeat_10m` | هر ۱۰ دقیقه | |
| `heartbeat_15m` | هر ۱۵ دقیقه | |
| `heartbeat_20m` | هر ۲۰ دقیقه | |
| `heartbeat_30m` | هر ۳۰ دقیقه | |
| `heartbeat_60m` | هر ۶۰ دقیقه | |
| `heartbeat_2h` | هر ۲ ساعت | |
| `heartbeat_12h` | هر ۱۲ ساعت | |
| `heartbeat_1d` | هر ۱ روز | |
| `heartbeat_3d` | هر ۳ روز | |
| `heartbeat_7d` | هر ۷ روز | |
| `heartbeat_15d` | هر ۱۵ روز | |
| `heartbeat_30d` | هر ۳۰ روز | |
