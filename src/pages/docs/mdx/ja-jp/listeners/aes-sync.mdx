---
title: AES sync
---

すべてのリスナーには、インプラントがメッセージの暗号化に使う通信用 AES キーを受け取るための通信インターフェースがあります。インプラントを特定のチームサーバーでコンパイルしたとき、ほかのチームサーバーもその AES キーを受け取って、インプラントからの通信メッセージを復号できるようにするためです。

## 仕組み

インプラントのコンパイル中、チームサーバーは設定済みサーバーの一覧を取り、設定済みの各リスナーへ、そのインプラントの通信用 AES キーを付けてリクエストを送ります。

ただし、その AES キーを受け取って保存するには、すべてのチームサーバーが同じ AES sync の secret key を持っている必要があります。違っていると、インプラントはコンパイルされたチームサーバーとしか通信しません。メッセージを復号できるのがそこだけだからです。

## 設定方法

1. チームサーバーで、次のコマンドを使います。

```bash
./nukerat.py server config set server.aes_sync.secret_key 1234567
```

この同じコマンドを、すべてのチームサーバーで実行する必要があります。

2. チームサーバーの設定ファイルで、設定を確認します。

```bash
./nukerat.py server config list
```

次のような結果が返るはずです。

```toml
[server.aes_sync]
secret_key = 1234567
sync_path = "/sync"
```

3. チームサーバーを再起動し、いつもどおりインプラントのコンパイルを続けます。

## Sync path

AES キーの同期パスを変えることもできます。その場合は、次のコマンドを使います。

```bash
./nukerat.py server config set server.aes_sync.sync_path /example
```

これは主に、デフォルトの HTTP チャネルを使っているときに、リスナー URL まわりのシグネチャを避けるのに役立ちます。
