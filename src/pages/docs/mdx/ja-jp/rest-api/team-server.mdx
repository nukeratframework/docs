チームサーバー向けの API エンドポイントです。

`/auth/login` を除くすべてのエンドポイントには `Authorization: Bearer <token>` ヘッダーが必要です。トークンは `/auth/login` から取得します。

---

### 認証

オペレーターの認証セッションを作成し、検証します。

<Collapsible className="mb-4">
  <CollapsibleTrigger className="flex w-full items-center gap-3 rounded-[11px] border border-fd-border bg-fd-card px-[15px] py-[10px] text-left text-sm font-medium">
    <span className="rounded-[6px] bg-emerald-500/15 px-2 py-1 font-semibold text-emerald-400">POST</span>
    <span className="font-[400] text-[16px]">/auth/login</span>
  </CollapsibleTrigger>
  <CollapsibleContent className="mt-3 rounded-lg border border-fd-border bg-fd-card p-4 text-sm text-fd-muted-foreground">
    <h2 className="api-section-title api-section-title--explanation">説明</h2>
    ユーザー名、パスワード、secret を用いてオペレーターを認証します。認証 JWT を返します。`user`、`pass`、`secret` のいずれかが欠落または空の場合、レスポンスは `{"status": "failure", "message": "user, pass and secret are required"}` になります。

    **重要:** `user`、`pass`、`secret` はチームサーバーで生成されたオペレーターキーから取り出す必要があります。例:


    ```
    admin:F9VhtamxN:yKu31sGWKXYPbnRq52cg
    ```

    上記の例では:

    
    **user** = `admin`<br/>
    **pass** = `F9VhtamxN`<br/>
    **secret** = `yKu31sGWKXYPbnRq52cg`<br/>

    <h2 className="api-section-title api-section-title--primary">リクエスト</h2>

    ```json
    {
      "user": "admin",
      "pass": "password",
      "secret": "secret"
    }
    ```

### AES キー

チームサーバー上に AES キー レコードを作成します。

<Collapsible className="mb-4">
  <CollapsibleTrigger className="flex w-full items-center gap-3 rounded-[11px] border border-fd-border bg-fd-card px-[15px] py-[10px] text-left text-sm font-medium">
    <span className="rounded-[6px] bg-emerald-500/15 px-2 py-1 font-semibold text-emerald-400">POST</span>
    <span className="font-[400] text-[16px]">/api/aes/create</span>
  </CollapsibleTrigger>
  <CollapsibleContent className="mt-3 rounded-lg border border-fd-border bg-fd-card p-4 text-sm text-fd-muted-foreground">
    <h2 className="api-section-title api-section-title--explanation">説明</h2>
    新しい tag と Base64 エンコードされた 32 バイト AES キーを生成し、両方をチームサーバーに保存します。

    <h2 className="api-section-title api-section-title--primary">リクエスト</h2>

    ```http
    POST /api/aes/create
    Authorization: Bearer <token>
    ```

    <h2 className="api-section-title api-section-title--explanation">説明</h2>
    インプラントにターミナル コマンドを送信します。

    <h2 className="api-section-title api-section-title--primary">特殊ケース: `-f` / `--file`</h2>

    ファイル バイトは次の 3 つのいずれかの方法で添付します:

    1. `command` 文字列の末尾に `--__tmp_file_bytes__` と Base64 ペイロードを追加する（NukeRat クライアントと同じ）。
    2. 別の JSON フィールド `__tmp_file_bytes__` に Base64 ペイロードを送る（`command` 文字列はそのまま）。
    3. リクエストボディを生のファイル バイトとして送り、`x-terminal-meta` ヘッダーに URL エンコードされた JSON メタデータを入れる（フィールドは JSON ボディと同じ）。サーバーは生ボディをアップロード ペイロードとして保存します。

    **例（インラインフラグ）:**


    ```
    upload -f payload.exe -o C:/Temp/payload.exe --__tmp_file_bytes__ SGVsbG8=
    ```

    <h2 className="api-section-title api-section-title--primary">特殊ケース: `download`</h2>

    `download` コマンドは `message` 内の Base64 を含む単一 JSON ボディを返しません。`Content-Type: application/x-ndjson` で応答します: 改行区切り JSON イベント（`progress`、続いて `chunk` メタデータと生バイト、最後に `success` または `failure`）。任意フィールド `download_id` と `download_file` はサーバーのダウンロード キューで進捗を追跡します。

    <h2 className="api-section-title api-section-title--primary">リクエスト</h2>

    ```json
    {
      "command": "whoami",
      "host_tag": "600d4",
      "source_terminal": "terminal_123"
    }
    ```

    <Callout type="info">
      `source_terminal` は必須ですが、リクエストを送ったクライアント ターミナルを識別するだけで、コマンド実行には影響しません。
    </Callout>
