团队服务端 REST API 端点。

除 `/auth/login` 外，所有端点均需 `Authorization: Bearer <token>` 请求头。通过 `/auth/login` 获取令牌。

---

### 认证

为操作员创建并校验认证会话。

<Collapsible className="mb-4">
  <CollapsibleTrigger className="flex w-full items-center gap-3 rounded-[11px] border border-fd-border bg-fd-card px-[15px] py-[10px] text-left text-sm font-medium">
    <span className="rounded-[6px] bg-emerald-500/15 px-2 py-1 font-semibold text-emerald-400">POST</span>
    <span className="font-[400] text-[16px]">/auth/login</span>
  </CollapsibleTrigger>
  <CollapsibleContent className="mt-3 rounded-lg border border-fd-border bg-fd-card p-4 text-sm text-fd-muted-foreground">
    <h2 className="api-section-title api-section-title--explanation">说明</h2>
    使用用户名、密码与 secret 认证操作员，返回认证 JWT。若 `user`、`pass` 或 `secret` 任一缺失或为空，响应为 `{"status": "failure", "message": "user, pass and secret are required"}`。

    **重要：** 须从团队服务端生成的操作员密钥中解析 `user`、`pass` 与 `secret`。例如：

    ```
    admin:F9VhtamxN:yKu31sGWKXYPbnRq52cg
    ```

    上例中：

    
    **user** = `admin`<br/>
    **pass** = `F9VhtamxN`<br/>
    **secret** = `yKu31sGWKXYPbnRq52cg`<br/>

    <h2 className="api-section-title api-section-title--primary">请求</h2>

    ```json
    {
      "user": "admin",
      "pass": "password",
      "secret": "secret"
    }
    ```


    <h2 className="api-section-title api-section-title--compact">响应</h2>

    <Tabs className="api-tabs" items={['Success', 'Failure']}>
      <Tab value="Success">
        ```json
        {

        ```
      </Tab>
      <Tab value="Failure">
        <Tabs className="api-tabs" items={['Credentials', 'Validation']}>
          <Tab value="Credentials">
            ```json
            {
              "status": "failure",

            ```
          </Tab>
          <Tab value="Validation">
            ```json
            {
              "status": "failure",
              "message": "Invalid request",
              "errors": [
                { "field": "<field>", "message": "<detail>" }
              ]
            }
            ```
          </Tab>
        </Tabs>
      </Tab>
    </Tabs>

    生成新 tag 与 Base64 编码的 32 字节 AES 密钥，并保存到团队服务端。

    <h2 className="api-section-title api-section-title--primary">请求</h2>

执行各类植入体交互，如终端、键盘记录、文件浏览器等。

    <h2 className="api-section-title api-section-title--explanation">说明</h2>
    向植入体发送终端命令。

    <h2 className="api-section-title api-section-title--primary">特殊情况：`-f` / `--file`</h2>

    以下列三种方式之一附加文件字节：

    1. 在 `command` 字符串末尾追加 `--__tmp_file_bytes__` 及 Base64 载荷（与 NukeRat 客户端相同）。
    2. 发送独立 JSON 字段 `__tmp_file_bytes__`（Base64 载荷，`command` 字符串保持简洁）。
    3. 以原始文件字节作为请求体，并在 `x-terminal-meta` 请求头中放入 URL 编码的 JSON 元数据（字段与 JSON 请求体相同）。服务端将原始请求体作为上传载荷保存。

    **示例（内联标志）：**

    ```
    upload -f payload.exe -o C:/Temp/payload.exe --__tmp_file_bytes__ SGVsbG8=
    ```

    <h2 className="api-section-title api-section-title--primary">特殊情况：`download`</h2>

    `download` 命令不会在 `message` 中返回带 Base64 的单一 JSON 体。响应 `Content-Type` 为 `application/x-ndjson`：按行分隔的 JSON 事件（`progress`，随后是 `chunk` 元数据与原始字节，最后是 `success` 或 `failure`）。可选字段 `download_id` 与 `download_file` 用于在服务端下载队列中跟踪进度。

    <h2 className="api-section-title api-section-title--primary">请求</h2>

    ```json
    {
      "command": "whoami",
      "host_tag": "600d4",
      "source_terminal": "terminal_123"
    }
    ```

    <Callout type="info">
      注意：`source_terminal` 为必填，但仅标识发送请求的客户端终端，不影响命令执行。
